# 코드 스타일 문서 독립 적용 리뷰

## 적용 조건

2026-09-04, 코드 기준 커밋 148cfbe에서 [코드 작성 기준](06-code-style.md)을 먼저 다듬고 새 서브에이전트 한 개를 생성했다. 이전 대화는 전달하지 않았다.

에이전트에는 문서 위치, MemoryEngine의 품질 개선 과제, 변경 가능한 파일만 전달했다. 개선 대상과 해결책은 스스로 선택하게 했으며 연관 코드·인터페이스·테스트를 읽도록 했다. 별도 에이전트 생성과 문서 수정은 허용하지 않았다. 실행 환경의 shell 오류를 해결하는 방법만 추가로 안내했다.

발견한 문제와 계획을 받은 뒤 그대로 구현하도록 요청했다. 구현 후 메인 에이전트가 코드와 테스트를 리뷰하고 전체 검증을 수행했다. 이번 판정 범위는 MemoryEngine의 개선 한 건이다.

## 에이전트가 선택한 문제

ResumePendingAsync에서 추출이 실패하면 내부 ExtractAndSaveObservationsAsync와 바깥 복구 처리 모두 FailSource를 호출했다.

첫 실패 기록 뒤 다른 Remember 요청이 같은 Source를 claim하면 두 번째 실패 기록이 새 시도의 processing 상태까지 failed로 바꿀 수 있다. 이 경쟁 가능성은 호출 흐름과 ClaimSource·FailSource의 SQL 조건으로 확인했다.

에이전트는 claim을 획득한 진입점이 실패 상태 기록을 책임지도록 정리했다.

- RememberAsync는 claim 이후 추출·저장을 감싸고 실패를 기록한다.
- ResumePendingAsync는 원문 읽기와 추출·저장의 실패를 처리한다.
- 내부 추출 함수는 실패를 호출자에게 전달한다.

Recall·Trace는 개선할 구체적인 이유를 찾지 못해 유지했다.

## 메인 리뷰

| 확인 항목 | 결과 |
| --- | --- |
| 실패 상태 기록의 책임 | 진입점에서 처리하며 같은 실패의 중복 기록을 제거했다. |
| 원문 파일 읽기 실패 | 복구 루프의 catch 범위에 남아 있다. 다음 Source 복구도 계속된다. |
| 취소 | 획득한 Source를 실패 상태로 남기고 취소를 전파한다. 이후 재시도가 가능하다. |
| 기존 처리 순서 | 정확 raw 중복 처리와 추출·임베딩·저장 순서를 유지했다. |
| 코드 구조 | 새 도우미·계층·컬렉션 복사 없이 책임을 옮겼다. |
| 변경 범위 | MemoryEngine과 관련 회귀 테스트로 한정했다. |

실패 상태를 기록하는 DB 작업 자체가 실패하는 경우도 별도로 검토했다. 복구 경로에서 중첩 catch가 우발적으로 수행하던 두 번째 상태 기록은 없어지고 DB 예외가 전파된다. 이 차이는 동작 변경으로 명시하며, 단순히 모든 동작이 같다고 평가하지 않는다.

수정은 채택했다. 코드에 대한 추가 수정 요청은 없었다.

## 문서에 반영한 피드백

에이전트는 문서가 실패 처리의 구체적인 소유 위치와 실패 기록 자체의 오류 정책까지 지정하지는 않는다고 보고했다. 소유 위치는 호출부와 상태 전이를 읽어 결정하는 것이 적절했다.

문서에는 실패 기록·자원 정리 자체의 실패도 검토하고, 예외 전파나 재시도 횟수의 변화는 동작 변경으로 설명해야 한다는 기준을 추가했다.

## 검증

기존 fixture와 실제 SQLite로 두 테스트를 추가했다.

- 원문 파일을 읽을 수 없어도 실패 상태를 기록하고 다른 Source를 복구한다.
- 복구 중 취소된 Source의 원문과 재시도 가능 상태가 유지된다.

기존 테스트를 포함한 전체 82개가 통과했다. 중괄호 스타일 검사와 git diff --check도 통과했다. 동시 요청의 특정 실행 순서를 강제하는 별도 경합 테스트는 추가하지 않았으며, 중복 기록 제거는 코드 흐름으로 검토했다.

이번 적용에서는 문서가 구체적인 문제 선택, 책임 배치, 불필요한 변경 자제에 필요한 기준을 제공했다.

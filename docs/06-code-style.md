# 코드 작성 기준

읽기 쉬운 코드는 적은 추측으로 실제 동작을 정확히 이해할 수 있는 코드다. 읽는 사람이 동시에 기억해야 할 상태와 전제를 줄이는 것을 우선한다.

## 표현

- 컬렉션 처리에는 가급적 LINQ 대신 명시적인 반복문과 컬렉션 메서드를 사용한다.
- if, else, for, foreach, while 등의 본문은 한 문장이어도 중괄호로 감싼다.
- 한 줄에 여러 동작을 압축하지 않는다. 단순한 속성이나 값 표현은 간결하게 유지한다.
- 변수는 역할과 소유권을 드러내야 한다. 특히 이월 작업의 원래 실행과 API 비용을 부담하는 현재 실행을 구분한다.
- 검증, 후보 수집, 정렬, 개수 제한, 외부 호출, 저장 순서를 눈으로 따라갈 수 있게 배치한다.

## 책임과 함수 경계

- 독립적인 작업 단위에 이름을 붙인다. 호출부가 그 이름만 읽고 세부 구현을 잠시 잊어도 되는지 확인한다.
- 서로 다른 책임이 섞여 있을 때 분리한다. 예를 들어 SourceArchive는 원문 파일을 보존하고, SqliteMemoryStore는 DB 등록과 트랜잭션을 책임진다.
- 파일 수, 함수 길이, 코드 줄 수를 목표로 삼지 않는다. 작은 도우미를 늘리기 전에 호출부와 구현을 오가는 비용을 고려한다.
- DB 쓰기, 유료 API 호출, 잠금, 자원 정리 같은 부작용은 이름과 호출 순서에 드러나야 한다.
- 주석에는 순서와 제약이 필요한 이유를 쓴다. 중요한 계약은 인터페이스와 실제 검증 지점 가까이에 둔다.

## 수정할 때 지킬 경계

- Remember는 정확히 동일한 raw를 LLM 호출 전에 중복 처리한다. 원문의 공백·개행을 정규화하지 않는다.
- Source 파일을 먼저 보존한 뒤 DB에 등록한다. 임시 파일의 정리 수명은 DB 커밋 이후까지 유지한다.
- Recall은 반환된 ID 전체를 검증한 다음 중복 제거와 결과 제한을 적용한다.
- 검색 결과의 동률 정렬, 후보 필터와 개수 제한의 순서, 그래프 방문 순서를 유지한다.
- 추상 기억은 같은 깊이의 부모와 B^depth 이상의 서로 다른 Source 근거를 가져야 한다. 사전 검증 후에도 저장 트랜잭션 안에서 다시 검증한다.
- Dream과 Meditation은 실행 시점의 입력 상한을 사용한다. 이월 작업은 원래 실행의 근거와 제안 식별자를 유지하며 API 비용만 현재 실행에 청구한다.
- API 호출 전 최대 비용을 예약한다. 사용량을 알게 되면 응답 거부·불완전·잘못된 제안을 판정하기 전에 정산하고, 사용량을 모르면 예약을 유지한다.
- 테스트는 이러한 계약의 구체적인 입력과 결과를 설명해야 한다. 구현 모양을 그대로 반복하는 테스트는 추가하지 않는다.

## 코드 탐색

- MemoryEngine: 공개 remember·recall·trace의 처리 순서.
- MemorySearch: 임베딩 준비, 키워드·벡터 검색, 순위 병합.
- ConsolidationEngine / MemoryScheduler: 근거 선택, 제안 보존·적용, 실행 기간과 재시도.
- SqliteMemoryStore / SourceArchive / SqliteSchema: 트랜잭션, 불변 원문, DB 제약.
- OpenAiCognition: 요청 구성, 비용 예약·정산, 응답 검증.
- AppHost / SchedulerWorker: 프로세스 초기화와 반복 작업 수명.

기본 서식과 중괄호 규칙은 루트의 .editorconfig에 지정한다. 검증은 dotnet test LongJourney.slnx --configuration Release로 실행한다.
